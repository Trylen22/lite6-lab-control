FOLLOW THE PIPELINE

From light
to a candidate.

Color detection is a sequence of small, inspectable decisions.

  1. 1

    Capture a frame

    Read a fresh color image from the OAK camera.

  2. 2

    Select a color range

    Convert BGR to HSV, then keep matching pixels.

  3. 3

    Find useful shapes

    Clean the mask and reject small or narrow regions.

  4. 4

    Describe the candidate

    Show its bounding box and image measurements.

BUILD UNDERSTANDING, ONE STEP AT A TIME

The learning path.

Each chapter has a clear experiment and a checkpoint before the next.

01
CURRENT PHASE

Observe & detect

Trace a frame from the OAK camera through OpenCV color thresholds or local YOLO. Read robot status without sending movement commands.

  • Compare raw, threshold mask, and annotated images.
  • Explain a centroid, a confidence score, and a false positive.
  • Verify stale frames never appear as fresh detections.
labdeck/color.py · yolo.py · robot.py
02
PLANNED · NO MOTION

Measure & calibrate

Confirm the camera mounting and tool geometry. Measure pixel, depth, camera, and robot coordinate frames with known reference points.

  • Record camera intrinsics and the camera-to-robot transform.
  • Measure error on reference points excluded from calibration.
  • Visualize proposed targets without executing them.
Checkpoint: validated measurements and documented uncertainty.
03
FUTURE · REQUIRES OPERATOR

Teach controlled motion

Verify mounting, emergency stop, tool/payload, clear workspace, speed limits, and explicit operator authorization before introducing any movement.

  • Teach this arm's poses and workspace boundaries.
  • Validate low-speed manual steps and stop behavior.
  • Keep observations separate from command execution.
Checkpoint: supervised motion validation.
04
FUTURE EXPERIMENT

Pick, place & explain

Develop an inspectable state machine: acquire → validate → approach → pick → transfer → release → verify.

  • Reject stale, uncertain, or out-of-workspace targets.
  • Handle lost objects and interrupted cycles explicitly.
  • Log what the system observed and why each action was selected.
Checkpoint: repeated supervised trials with measured outcomes.

SESSION BOUNDARIES

What is running here

Frames and detections are processed locally. The dashboard serves only this laptop. No automatic recording, cloud inference or movement on page load is enabled. The Pick & Place button requests one guarded robot and suction cycle.

Color thresholds describe appearance. YOLO predictions describe learned classes. Green pickup uses a separately validated tabletop profile; YOLO classes do not trigger motion.

The README, architecture guide, and lesson plan explain how to run, inspect, and extend each part.
